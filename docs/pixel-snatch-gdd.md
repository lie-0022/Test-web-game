## 1. 개요

- **타이틀(가제):** PIXEL SNATCH
- **장르:** 모바일 웹 픽셀 .io (루팅 아레나 + cash-out)
- **한 줄:** "작은 픽셀 도둑이 되어, 경보가 울리기 전에 더 많이 들고, 출구에 산 채로 닿아라."
- **시점:** 탑다운 2D, 세로형 480×854(고정 내부 해상도, FIT 업스케일)
- **세션:** 60–90초 한 매치, 탭 1회로 재시작
- **핵심 동사:** 줍는다 / 흘린다 / 도망친다 / **확정한다(cash-out)**
- **비유 게임:** Paper.io 2(봇 모델) · Hole.io(수집 루프) · 익스트랙션 게임의 cash-out 긴장(단순화)

### 차별점 한 줄

대부분의 .io는 점수를 "확정"시키지 못한다. PIXEL SNATCH는 매 순간 *"지금 은행에 넣을까,
한 줌만 더 노릴까"* 의 결정을 강제한다. 그 결정 순간이 클립거리가 된다.

## 3. 코어 게임플레이 루프

### 한 매치(60초)의 흐름

```
[탭] → 매치 시작
 ├─ 0–10s   : 분산된 코인을 쉽게 수집 (긴장 낮음)
 ├─ 10–35s  : 코인 경쟁, 도둑 충돌, 안전 구역 줄어듦 (긴장 중)
 ├─ 35–55s  : 안전 구역 좁아짐, 흘리는 보물 ↑, cash-out 결정의 골든타임
 └─ 55–60s  : 마지막 출구 러시
[라운드 종료] → 결과 화면(은행 점수, 베스트 갱신 여부) → [탭] 재시작
```

### 컨트롤

- **이동:** 화면을 누른 상태로 드래그 — 도둑이 손가락 위치를 향해 이동.
- **그 외 버튼 없음.** 모바일 웹의 보편적 마찰을 최소화. cash-out도 자동(출구 띠에 진입 시
  적재량을 자동으로 은행에 입금).
- **데스크톱:** 마우스 클릭+드래그로 동일 동작 (Phaser pointer가 마우스/터치 통합).

### 메타루프(매치 사이)

```
매치 종료
 ├─ 베스트 갱신 / 일일 갱신 시 짧은 셀러브레이션
 ├─ (옵션) 보상형 광고 — "1.5× 점수로 변환"
 ├─ 인터스티셜 광고 (3매치마다, A3 가정)
 └─ 탭하면 즉시 다음 매치
```

## 4. 메커닉

### 4.1 도둑(플레이어/봇 공통)

| 속성 | 값(현재) | 비고 |
|------|----------|------|
| 베이스 속도(플레이어) | 185 px/s | 적재량에 따라 감속 |
| 베이스 속도(봇) | 130 px/s | 봇 종류별로 ±20 (§5에서 정의) |
| 적재량 감속 공식 | `speed = base / (1 + loot × 0.018)` | loot 50 → 약 절반 속도 |
| 충돌 반경 | 20 px | 도둑끼리, 출구 진입 판정 |
| 흘림 비율 | 30% (max 1) | 충돌 시 더 많이 든 쪽이 흘림 |
| 흘림 쿨다운 | 0.6s | 매 프레임 발동 방지 |

### 4.2 코인 / 보물

v0.1은 **코인 한 종류**만. v0.5에서 추가.

| 종류 | 가치 | 출현 | 비고 |
|------|------|------|------|
| 코인 (현재) | 1 | 항상 (26개 유지, 0.7s 보충) | 평범 |
| 보석 (v0.5) | 5 | 매치당 3–4개, 안전 구역 끝자락 | 위험-보상 |
| 금괴 (v0.5) | 15 | 보스 챔버 1회, 마지막 10초 등장 | "마지막 욕심" 유도 |

설계 의도: v0.1은 단일 코인으로 메커닉 검증. v0.5에서 가치 계층을 도입해 의사결정 깊이를 늘림.

### 4.3 적재 & 감속

- 적재량이 많을수록 느려진다. 50 코인 시점에서 약 50% 속도 → 출구까지 위험.
- 시각적 피드백 필요: 적재량에 따라 도둑 스프라이트 위에 코인이 쌓이는 미니 아이콘.
- **튜닝 목표:** "10 코인까지는 부담 없음, 20부터 망설임, 40 이상은 폭탄" 체감.

### 4.4 도둑 충돌 / 흘리기

- 두 도둑이 20px 이내로 접근 시, 더 많이 든 쪽이 적재의 30%를 코인으로 토해냄(주변 ±22px).
- 같은 양이면 흘림 없음(데드락 방지).
- **트위스트:** 적게 든 도둑이 많이 든 도둑을 일부러 들이받아 흘리는 전략 가능 → "약자도 사냥꾼".
- v0.5: 충돌 시 짧은 스턴(0.2s) + 화면 진동(저강도) 추가 검토.

### 4.5 안전 구역 (Shrinking Zone)

- 매치 시작 시 GAME_WIDTH × 0.62 반경 원형 구역, 8 px/s로 축소(최소 반경 90px).
- 구역 밖에 있고 적재 > 0인 도둑은 0.7초마다 코인 1개를 흘림(자동 드레인).
- 봇에도 동일 적용 → 약자가 구역 가장자리에서 봇의 흘림을 주워먹는 플레이 가능.
- **튜닝 목표:** 매치 후반에는 출구 근처가 안전 구역 안에 남도록 위치/축소 속도 조정.

### 4.6 Cash-out (출구)

- 화면 하단 노란 띠. 도둑이 진입하면 적재 전체를 은행에 즉시 입금, 적재 0으로 리셋.
- **시각/청각 피드백:** 입금 시 노란 텍스트 `+N` 위로 튀어오름 + (v0.5) "차링" SFX.
- 봇도 cash-out 가능 — 단, 점수는 표시만 하지 않고 단순히 흘리던 코인이 사라짐(플레이어 점수만
  추적).

### 4.7 라운드 종료

- 60초 → 종료. 들고 있던 적재량은 **날아감**(은행 점수만 인정) → cash-out 결정의 가치 강화.
- 결과 화면: 은행 점수, 들고 있다 날린 양, 베스트 갱신 표시, 탭 = 재시작.

### 4.8 봇 페이크 멀티플레이

- 매치마다 4명의 봇이 함께. UI는 멀티플레이처럼 보이지만 실제로는 로컬 시뮬레이션.
- 봇 색은 빨강, 플레이어는 초록. v0.5에서 봇별 닉네임(`Player_xxxx`) 표시 + "ONLINE" 가짜 표시.
- §5 봇 AI 참조.

## 5. 봇 AI

콘셉 리서치 §3-1이 "가장 어려운 부분"으로 지목한 영역. 인간처럼 *욕심·당황·실수* 가 보여야 함.

### 5.1 행동 상태(FSM)

```
            ┌──────────┐
            │  HUNT    │ 가장 가까운 코인으로 이동
            └────┬─────┘
   적재 임계치 ↑  │  ↓ 충돌 직후
            ┌────▼─────┐
            │ CASH_OUT │ 출구로 직진
            └────┬─────┘
   입금 완료  ↓   │  ↑ 큰 도둑 근접 → 회피
            ┌────▼─────┐
            │  EVADE   │ 가장 위협 큰 도둑 반대 방향
            └──────────┘
```

v0.1 현재: HUNT만 구현(가장 가까운 코인). v0.5에서 CASH_OUT/EVADE 추가.

### 5.2 봇 종류 (개성)

| 타입 | 임계치 | 욕심 | 속도 | 효과 |
|------|--------|------|------|------|
| GREEDY | 적재 50에 cash-out | ★★★ | -10 | 잘 흘림, 큰 사냥감 |
| TIMID | 적재 15에 cash-out | ★ | +10 | 빠른 출구, 작은 보상 |
| BRAWLER | 적재 30, 작은 도둑 사냥 | ★★ | 0 | 일부러 충돌 |
| WANDERER | 임계치 없음, 무작위 | ★★ | 0 | 예측 불가 |

매 매치 4명을 위 타입에서 무작위로 추첨(중복 가능). 다양한 매치 체감 생성.

### 5.3 "인간처럼 보이기" 트릭

- 가끔 잘못된 코인을 선택(10% 확률로 두 번째 가까운 코인 선택)
- 출구 직전에서 0.3s 망설임(작은 정지)
- 좁은 안전 구역에서 패닉 — 짧게 떨림(±5px)

이 트릭들은 v0.5에서 도입, A/B 테스트로 검증.

## 6. 메타게임 (얇게)

CLAUDE.md "단순함 우선" 원칙. v1은 다음만:

### 6.1 로컬 저장 (localStorage)

| 키 | 의미 |
|----|------|
| `bestScore` | 역대 최고 은행 점수 |
| `bestToday` | 오늘 자정 기준 최고 |
| `streakDays` | 연속 플레이 일수 |
| `unlockedSkins` | 잠금 해제된 스킨 ID 배열 |

### 6.2 스킨 (코스메틱만)

| 스킨 | 잠금 해제 조건 |
|------|---------------|
| 기본 (초록) | 시작 |
| 골드 도둑 | 단일 매치 100점 달성 |
| 닌자 (검정) | 5일 연속 플레이 |
| (v1.5+) IAP 스킨 | 결제 |

게임플레이 영향 없음 — 색상만 다름. 픽셀 아트 자체가 픽셀 도둑이라 8×8 색 팔레트 교체로 끝.

### 6.3 일일 시드 (옵션, v1.5)

같은 날 모든 플레이어가 동일한 코인 배치/봇 타입 시드를 받음. "오늘의 도전" 점수 비교용.
백엔드 필요 없이 시드만 공유 — 로컬 리더보드(친구 코드 입력)부터 시작 가능.

### 6.4 명시적 미포함 (v1 스코프 외)

- 길드/팀
- 시즌 패스
- 캐릭터 레벨업
- 무기/스킬 (cash-out 단순함을 깨뜨림)
- 채팅
- 실시간 PvP

위 항목은 가정 A1·A2가 뒤집힐 때만 검토.

## 7. 수익화

### 7.1 v1.0

- **인터스티셜 광고:** 매 3매치 후 1회. 매치가 짧기 때문에 마찰 최소화.
- 광고 SDK는 미정 — 후보:
  - **CrazyGames SDK** (포털 배포 시 가장 자연스러움)
  - **Poki SDK** (라이선싱 모델)
  - **Google AdSense for Games** (자체 호스팅 시)
- **보상형 광고(옵션):** 결과 화면에서 "광고 시청 → 점수 1.5×". 한 매치당 1회만.

### 7.2 v1.5

- **스킨 IAP:** ₩1,500–3,000 가격대. Stripe/포털 결제.
- 점수 자체에 IAP 영향 없음(공정성 유지).

### 7.3 미정 결정

- 광고 SDK 최종 선택(자체 호스팅 vs 포털 라이선싱)
- 무광고 ₩ 결제 옵션 도입 여부
- 서버 점수 검증 — 자체 백엔드 도입 시점

## 8. 밸런싱 수치 (현재 + 튜닝 목표)

현재 프로토타입 값(`GameScene.ts`)과 튜닝 목표. **§3.1 매치 흐름 의도와 일치하는지가 기준.**

| 변수 | 현재 | 목표(v0.5) | 노트 |
|------|------|------------|------|
| `ROUND_TIME` | 60s | 60–75s | 60s가 짧으면 75s로 |
| `COIN_TARGET` | 26 | 20–30 | 코인 밀도 |
| 코인 보충 주기 | 0.7s | 0.5–1.0s | 후반 희소성을 위해 후반 ↑ |
| `BOT_COUNT` | 4 | 3–5 | 화면 혼잡도 |
| `PLAYER_SPEED` | 185 | 180–200 | 봇 대비 약간 우위 |
| `BOT_SPEED` | 130 | 110–145 | 봇 타입별 가변 |
| 감속 계수 | 0.018 | 0.015–0.022 | "20에서 망설임" 체감 |
| 흘림 비율 | 30% | 25–35% | 사냥의 보람 |
| 흘림 쿨다운 | 0.6s | 0.5–0.8s | 너무 잦은 흘림 방지 |
| 안전 구역 축소 | 8 px/s | 6–10 px/s | 매치 끝까지 안전 구역이 출구 덮도록 |
| 안전 구역 최소 반경 | 90 | 80–110 | 막판 혼잡도 |
| 드레인 주기 | 0.7s/코인 | 0.5–1.0s | 구역 밖 페널티 강도 |

**튜닝 검증 방법:** 봇 vs 봇 매치를 60회 자동 실행 → 평균 은행 점수 분포 측정. "타입별 평균
점수"가 의도한 곡선(GREEDY > BRAWLER > WANDERER > TIMID)에 근접하는지 확인.

## 9. 온보딩

첫 30초가 가장 중요. v1 기준:

- **튜토리얼 없음 — 인-게임 학습.** 첫 매치는 봇 1명만, 안전 구역 축소 없음, 코인 풍부.
  플레이어가 자연스럽게 *줍기 → cash-out* 을 발견.
- **첫 라운드 종료 화면:** "은행 N. 들고만 있던 M은 날아갔다 — cash-out 해야 점수가 됨" 명시.
- **두 번째 매치:** 봇 3명, 안전 구역 활성화. 정상 난이도.
- **로딩 화면 카피:** "출구에 닿아야 점수가 된다" — 코어 메커닉을 한 줄로.

## 11. 기술 / 성능 타깃

- **렌더:** 480×854 내부, FIT 업스케일. `pixelArt: true`, `roundPixels: true`.
- **FPS:** 60 mid-end, 30 low-end Android (Chrome). iOS Safari 60.
- **콜드 스타트:** < 3s on mid-end 4G
- **세션 페이로드:** < 3MB(스프라이트 아틀라스 1개, 비트맵 폰트 1개, audio sprite 1개)
- **메모리:** < 100MB during play
- **의존성:** Phaser 3.88, TypeScript 5.6, Vite 5.4. v0.5에서 Howler.js 추가.
- **모바일 우선:** `touch-action: none`, viewport meta, 44px+ 터치 타깃(현재 출구 띠 64px ✓),
  `devicePixelRatio` 캡 (필요 시 2로 한정).
- **오브젝트 풀링:** 코인/흘림 텍스트는 풀로 재사용(v0.5 리팩터링 시).
